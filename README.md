# mhxy_agent

> 《梦幻西游》电脑版五开长期运营 AI Strategy Brain：面向新区开荒、角色成长、五开扩展、任务调度、收益分析、资源投资与自动化任务规划。

## 项目定位

本项目不是传统的“攻略文章生成器”，而是一个围绕《梦幻西游》电脑版长期运营场景设计的策略规划框架。核心目标是根据**当前版本、新区环境、队伍配置、资金、装备/宝宝、时间成本以及历史运行数据**，持续回答一个问题：

> **对于当前这个五开队伍，现在做什么最划算？**

最终优化目标不是单纯追求等级，而是：

**单位时间长期净收益最大化 + 运营稳定性最大化 + 角色资产增值 + 自动化执行效率最大化。**

## 核心能力

- 游戏版本与规则分析
- 新区开荒与经济周期规划
- 单号 → 双开 → 三开 → 四开 → 五开成长规划
- 角色、技能、修炼、法宝、装备、宝宝投资优先级
- 任务收益、时间成本、资源消耗与风险综合评估
- 每日/每周任务调度
- 升级 vs 停级经济学决策
- 69 / 89 / 109 / 129 / 159 / 175 等关键节点复盘
- 五开搬砖净收益与回本周期计算
- 基于真实运行数据持续优化任务优先级
- 面向自动化 Agent 的 Machine Action Plan
- Action → Observe → Verify 的可验证执行机制
- 掉线、死亡、卡死、导航失败、背包满等异常恢复
- 高价值/不可逆操作安全控制

## 策略总流程

```text
观察数据
  ↓
读取知识
  ↓
识别当前游戏状态
  ↓
分析经济与任务
  ↓
计算收益 / 成本 / 风险
  ↓
规划成长与投资
  ↓
生成今日/本周任务队列
  ↓
转换为可执行任务计划
  ↓

  ↓
重新评估并持续优化
```

## 知识来源优先级

项目要求严格区分事实、经验与推测，并遵循以下优先级：

1. **官方公告 / 当前游戏实际规则**
2. **当前版本可靠资料**
3. **xyq-skills 知识库**：https://github.com/MikiVision/xyq-skills
4. **当前服务器 / 新区实际数据**
5. **长期玩家经验**
6. **历史攻略**
7. **AI 推测**

当来源冲突时，优先使用更高等级来源。**禁止把历史版本攻略直接当成当前版本事实。**

### 知识库使用原则

`xyq-skills` 被视为 **Knowledge Layer**，用于游戏机制、任务、战斗、活动、宠物、装备、技能、系统、经济、工具和常见问题等知识参考。

知识库内容不应直接复制到业务规则中，更不应把知识库等同于 Hardcoded Rule Layer。

## 知识可信度

重要结论应标注可信度：

| 等级 | 含义 |
|---|---|
| A | 官方确认 / 当前实测 |
| B | 可靠知识库 / 多来源确认 |
| C | 长期玩家经验 |
| D | 历史数据 |
| E | AI 推测 |

使用 C / D / E 级数据时，应明确标记为 `【经验数据】`、`【历史数据】` 或 `【推测数据】`，禁止伪装成官方数据。

每次进行复杂规划，都应先建立或更新 `Game Profile`，而不是只根据一句自然语言直接给出固定攻略。

建议至少记录：


信息缺失时必须写 `【未知】` 或 `待确认`，不得擅自假设。

## 五开状态机

```text
STATE_0   单号起步
STATE_1   单号成长
STATE_2   准备第二号
STATE_3   双开
STATE_4   准备第三号
STATE_5   三开
STATE_6   准备第四号
STATE_7   四开
STATE_8   五开准备
STATE_9   五开基础成型
STATE_10  五开稳定运营
STATE_11  五开收益优化
STATE_12  长期搬砖
```

每次分析必须判断：

- 当前处于哪个状态；
- 下一状态的进入条件；
- 是否应该继续扩号；
- 如果暂时不适合五开，应明确说明“暂时不要开第五个号”等结论及经济学原因。

## 等级与转型决策

项目不采用“高等级 = 高收益”的简单假设。每次到达关键等级节点，需要重新评估：

- 是否继续升级 / 停级
- 是否增加账号
- 是否提升装备、技能、修炼、宝宝、法宝
- 是否开始或转型搬砖任务体系
- 升级新增收益是否足以覆盖新增投入

默认重点观察：

```text
0 → 20 → 30 → 40 → 50 → 60 → 69 → 89 → 109 → 129 → 159 → 175
```

当前版本如果出现更合理的节点，应允许动态调整。

### 升级回本模型

```text
回本时间 = 升级总投入 / 升级后每小时新增净收益
```

升级决策应至少比较：新增任务、新增收益、新增装备/宝宝/修炼/技能要求以及额外时间成本。

## 任务评价模型

不能只说“这个任务收益高”，而应拆分并计算：

- 经验价值
- 现金收益
- 可交易物品价值
- 储备金收益
- 角色成长价值
- 潜在资产价值
- 时间成本
- 消耗成本
- 风险成本
- 五开效率
- 操作复杂度
- 稳定性

核心思路：

```text
Task Score
= 经验价值
+ 现金价值
+ 物品价值
+ 储备金价值
- 时间成本
- 消耗成本
- 风险成本
```

### 收益分类必须独立统计

严禁把：

```text
现金 100万
+ 储备金 100万
+ 物品 100万
```

直接写成“收益 300 万”。应分别统计 `Cash / Reserve / Tradable Items / Non-tradable Items / Growth Profit`。

## 任务稳定性

除理论收益外，应维护 `Stability Score`，考虑：

- 掉落随机性
- 市场波动
- 任务波动
- 组队要求
- 操作复杂度
- 失败概率

可分为：

```text
S：稳定高收益
A：高收益
B：稳定收益
C：随机收益
D：不建议
```

### Expected Value

实际策略优先考虑 `Expected Profit`，而不是理论收益。例如理论收益 100 万但成功率只有 60%，则有效期望收益应显著低于 100 万，并继续扣除失败成本。

## 每日 / 每周任务规划

用户应提供每日在线时间，例如 2 / 4 / 6 / 8 小时。系统根据等级、五开状态、服务器、活动、资源、任务刷新和时间预算生成 `Today Task Plan`，而不是无视时间限制地把所有任务都列出来。

### 今日任务队列

```text
01. 任务
预计时间：
收益：
优先级：

02. 任务
预计时间：
收益：
优先级：
```

任务优先级：

```text
P0：必须立即处理
P1：高收益任务
P2：日常任务
P3：低优先级任务
P4：收益过低
P5：当前阶段禁止
```

### 优化目标

```text
Maximize Net Profit / Hour
```

而不是最大化绝对总收益。在线时间越短，越应优先高边际收益任务；在线时间较长时，再补充稳定但低收益任务。

## 资源与投资模型

### 角色投资

五个角色不能平均投资，应区分：

```text
Main Carry
Secondary Carry
Support
Support
Support
```

所有投资都要考虑 `Marginal ROI`。例如同样增加 100 万预算，应优先投入到单位投资带来更高收益提升的位置。

### 装备 / 宝宝 / 技能 / 修炼 / 法宝

每笔投入都应回答：

- 成本多少
- 收益提升多少
- 预计使用多久
- 是否存在更便宜替代方案
- 回本多少小时
- 边际收益是否仍然足够高

重点投资顺序不能机械模板化，必须结合门派、当前任务和新区物价。

宝宝建议按：

```text
系统宝宝 → 过渡宝宝 → 任务宝宝 → 高效率宝宝 → 成品宝宝
```

避免为了“看起来高级”而提前购买高价宝宝。

### 资金分配

```text
Operating Cash
Equipment
Pets
Skills
Cultivation
Magic Weapons
Emergency Fund
Investment
```

必须保留 `Emergency Fund`，不能一次性把所有现金投入角色。

## 新区经济系统

新区策略重点关注：

- 什么应该立即卖
- 什么应该留存
- 什么应该自用
- 什么适合投资
- 什么会随着等级开放而涨价
- 什么会快速贬值

形成 `New Server Economic Cycle`，并将掉落物品归类到：

```text
SELL_NOW
KEEP
USE
INVEST
WAIT
DISCARD
```

## 收益统计与实测

每日建议记录：

```text
Start Capital
End Capital
Cash Profit
Item Profit
Reserve Profit
Growth Profit
Consumption
Net Profit
Hours
Net Profit / Hour
```

不要只采用理论收益，支持 10 / 20 / 50 / 100 小时等真实测试，并观察：

- 平均收益
- 中位数
- 最大值
- 最小值
- 标准差
- 成功率 / 失败率

样本不足时必须降低结论置信度。短时测试只能作为初步估计。

## 自动化 Agent 设计

当本项目用于自动任务 Agent 时，规划结果必须能够转换为 `Machine Action Plan`。

例如“抓鬼”可以展开为：

```text
1. 检查队伍
2. 检查角色状态
3. 领取任务
4. 定位目标
5. 导航
6. 进入战斗
7. 执行战斗策略
8. 验证战斗结果
9. 领取奖励
10. 进入下一轮
```

### Action 必须可验证

禁止“点击之后直接认为成功”。统一采用：

```text
Action
  ↓
Observe
  ↓
Verify
```

例如：

```text
CLICK_NPC
↓
检测 NPC_DIALOG == TRUE
↓
SUCCESS
```

## 异常恢复与安全

运行中可能出现：

- 掉线
- 卡死
- 死亡
- 战斗异常
- 地图异常
- NPC 异常
- 任务失败
- 队伍散队
- 窗口失焦
- 弹窗
- 背包满
- 资源不足

必须设计 `Recovery Strategy`，并按优先级处理：

```text
P0：Emergency
P1：死亡 / 掉线 / 队伍异常
P2：任务失败
P3：导航失败
P4：普通 Action 失败
```

自动化安全规则：默认禁止自动执行以下不可逆或高风险操作：

- 删除角色
- 删除高价值装备
- 丢弃高价值物品
- 高价值交易
- 其他不可逆操作

除非用户已经明确授权。

首次运行时，系统应依次：

1. 确定当前版本
2. 确定服务器
3. 确定新区开区时间
4. 确定 5 个账号状态
5. 确定等级、门派、资金、装备、宝宝、技能、修炼
6. 确定每日在线时间
7. 生成《当前阶段最优成长方案》
8. 生成《未来 30 天路线》
9. 生成《五开转型节点》
10. 生成《当前任务优先级》

**不要直接输出泛泛攻略。**

## 面向常见问题的决策规则

### “现在做什么”

只需要聚焦：

```text
NOW
NEXT
LATER
DO NOT
```

### “这个东西值不值得买”

至少计算价格、收益提升、使用周期、替代方案、回本时间与边际收益，最终给出：

```text
BUY / WAIT / DO NOT BUY
```

### “要不要升级”

至少给出：

```text
当前等级
升级成本
升级后新增内容
预计新增收益
预计新增投入
回本时间
UPGRADE / STAY
```

### “今天做什么”

根据等级、五开状态、服务器、当天日期、活动、时间与资源生成 `Today Task Plan`。

### “怎么搬砖”

不能直接罗列固定任务。必须先判断等级、五开状态、资金、装备、宝宝、每日时间、新区经济，再计算、排序并输出最优任务组合。

## 核心原则

1. 等级不是最终目标。
2. 五开不是越早越好。
3. 高等级不等于高收益。
4. 高收益不等于高净收益。
5. 现金不等于储备金。
6. 物品价值不等于现金。
7. 理论收益不等于实际收益。
8. 五个角色不能平均投资。
9. 投资必须考虑边际收益。
10. 升级必须计算回本周期。
11. 停级必须有经济学依据。
12. 新区必须考虑物价周期。
13. 任务必须考虑五开效率。
14. 必须考虑失败率。
15. 必须考虑时间成本。
16. 必须考虑操作成本。
17. 必须考虑长期稳定性。
18. 不确定信息必须标记。
19. 不允许虚构数据。
20. 不允许把旧版本当当前版本。
21. 不为了凑内容推荐低收益任务。
22. 不因为某等级“经典”就默认停级。
23. 不因为某门派流行就默认最优。
24. 必须根据当前实际状态动态规划。
25. 最终目标是：**稳定、低投入、高效率、可持续的五开搬砖体系。**
